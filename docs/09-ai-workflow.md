# 把 AI 当排障副驾：有效的问法、误判和边界

> 这篇不是“AI 一键搞定”的爽文。它记录的是：AI 哪些地方真的省时间，哪些地方会把你带沟里。

## 1. 角色定位

AI 适合做：

- 读英文日志/文档，提炼关键词；
- 根据现象列假设，按概率排序；
- 生成/解释命令；
- 对比两份配置的差异；
- 把排障过程整理成可复现文档。

AI 不适合做：

- 替你确认“现在到底哪根线插在哪”；
- 替代 `ip addr`、`ss -ltnp`、`Get-NetTCPConnection` 的现场证据；
- 在你不理解命令后果时直接执行；
- 保证它给的路径、端口、配置项一定存在。

一句话：**AI 是副驾，不是自动驾驶。**

## 2. 一个有效的提问模板

不要问：

```text
Deskflow 连不上怎么办？
```

要问：

```text
环境：
- Windows 11 做 Server，Linux 做 Client
- Windows 直连网卡 IP：169.254.230.111
- Linux eno1：10.10.10.2/24
- Deskflow 1.27.0，24800 没有监听

现象：
- 客户端提示 connection failed
- 服务端 GUI 日志：daemon failed to start process, error: vector too long

请：
1. 按可能性从高到低列原因；
2. 每一项给一个验证命令；
3. 不要直接让我改配置，先告诉我怎么确认。
```

关键要素：

- **环境**：OS、版本、角色、IP；
- **现象**：完整报错，不要只写“连不上”；
- **证据**：日志、`ip addr`、端口状态；
- **约束**：不要暴露公网、不要重装、不要动某个配置；
- **输出格式**：按概率排序、给验证命令。

## 3. 证据优先级

我实际使用的优先级：

```text
现场命令输出 > 程序日志 > 官方文档 > 社区帖子 > AI 的记忆/猜测
```

例子：

- AI 根据残留 ARP 条目猜 Linux 是 `10.20.71.1`；
- 实际 `ip addr` 显示 `10.10.10.2/24`；
- 以 `ip addr` 为准，改 Windows 到 `10.10.10.1/24`，立刻通。

再比如：

- AI 建议在 `deskflow-server.conf` 写 `section: screens`；
- core 报 “Screens have moved to the general config”；
- 以程序日志为准，改到 `Deskflow.conf`。

## 4. AI 在这次排障里做对的几件事

### 4.1 从 `vector too long` 联想到路径编码

它没有直接说“重装”，而是建议检查安装路径是否含中文/过长。这个方向是对的：把目录移到 `C:\Tools\Deskflow` 后，core 就能起来了。

### 4.2 识别“重复实例”

看到 `daemon ipc ... 无效名称` 和 `OpenClipboard` 同时出现，它判断是旧 GUI 和新 core 抢资源。关掉旧 GUI 后，错误消失。

### 4.3 解释 TLS 指纹

`fingerprint does not match trusted fingerprint` 不是“网络不通”，而是证书信任没建立。它给出了 `checkPeerFingerprints=false` 的临时方案，以及“只建议可信网络”的边界。

### 4.4 把配置模型讲清楚

1.27 的 screens 在通用配置、links 在 server 配置，这个变化很容易踩。AI 根据报错把两处拆开，省了翻文档的时间。

## 5. AI 猜错的地方

### 5.1 根据残留 ARP 猜 IP

邻居表里有一个 `10.20.71.1` 的 `Unreachable` 条目，AI 建议把 Windows 设成 `10.20.71.2/24`。结果 ping 不通。真正有效的是 Linux 的 `ip addr`。

**教训**：ARP 条目会残留，不能当“对端在线”的证据。

### 5.2 在 server 配置里写 screens

AI 按旧版 Synergy 的经验给了 `section: screens`，但 1.27 已经迁移。程序日志直接打脸。

**教训**：版本变化会让“经验”失效，先看当前版本的报错。

### 5.3 把“能 ping 通”当成“端口通”

ping 通只说明 IP 层通；24800 可能被防火墙拦，或者服务端没监听。

**教训**：用 `Test-NetConnection -Port` / `nc -vz` 测端口，不要只看 ping。

### 5.4 忽略“复制的是文件不是图片”

一开始我们都以为“图片不能传”，后来才发现是资源管理器里复制了 PNG 文件。剪贴板格式是 `CF_HDROP`，不是 bitmap。

**教训**：先确认剪贴板里到底是什么格式。

## 6. 安全护栏

用 AI 排障时，我给自己定了几个规矩：

1. **改配置前备份**  
   `Deskflow.conf`、`smb.conf` 先复制一份。

2. **一次只改一个变量**  
   同时改 IP、防火墙、绑定，出了问题不知道是谁的锅。

3. **不把公网当实验场**  
   24800/445 只在直连/局域网开放；不用 `checkPeerFingerprints=false` 连公共 Wi-Fi。

4. **不把密码/密钥贴给 AI**  
   需要共享的配置，先脱敏。

5. **不执行看不懂的命令**  
   尤其是 `Remove-*`、`Set-NetFirewallProfile`、`rm -rf`、`chmod 777`。

6. **让 AI 给验证命令，而不是只给结论**  
   “怎么确认”比“应该是”更有价值。

## 7. 一个可复用的排障 prompt

```text
你是我的网络/系统排障副驾。不要直接下结论，先按层排查。

环境：
- OS/版本：
- 角色（Server/Client）：
- 两端 IP/掩码/网关：
- 软件版本：
- 相关端口：

现象：
- 完整报错：
- 发生时间：
- 最近改过什么：

已确认：
- 网卡状态：
- ping 结果：
- 端口监听/连通性：
- 日志关键行：

请输出：
1. 最可能的 5 个原因，按概率排序；
2. 每个原因对应的验证命令；
3. 每个原因的修复方案和风险；
4. 如果信息不足，告诉我下一步该收集什么。
```

## 8. 最后的边界

AI 能帮你更快地找到“可能是路径问题”“可能是 TLS”“可能是重复实例”，但它不能替你承担：

- 改错防火墙导致远程断连；
- 把 24800 暴露到公网；
- 在没备份的情况下改配置；
- 把“AI 说的”当成“系统事实”。

**AI 降低的是学习成本，不是责任成本。**
