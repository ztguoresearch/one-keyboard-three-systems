# 为什么成品 USB 对拷线救不了 Linux

## 先说结论

**大多数“USB 对拷线”不是不能用，而是它的“文件互传”只支持 Windows/macOS。**

Linux 下常见的结局是：

- 键鼠共享勉强可用（HID 模拟）；
- 文件互传不可用（厂商客户端没有 Linux 版）；
- 部分型号连识别都不稳定。

所以如果你的目标是“Linux 和 Windows 之间共享键鼠 + 传文件”，对拷线通常不是正确答案。

## 对拷线到底是怎么工作的

一条真正的 USB 对拷线，中间不是简单的铜线，而是一颗 **USB 桥接芯片**。常见方案：

- Prolific PL25A1 / PL27A1；
- 其他厂商的 USB 3.0 host-to-host 桥接芯片。

它让两台电脑的 USB 主机口“背靠背”连接，然后由厂商软件完成：

1. 建立一条专用数据通道；
2. 在两端显示“文件传输”界面；
3. 处理键鼠共享、剪贴板、文件列表。

关键在 **第 3 步的软件**。硬件只负责“通”，软件才决定“能做什么”。

## Linux 为什么经常缺席

Linux 内核并不是完全不支持这些芯片。比如 PL27A1 在 `plusb` 驱动里有支持，会创建一个 `usb0` 网络接口，Linux↔Linux 可以通过 IP 通信。

但厂商的“一键互传”客户端通常是：

- Windows 上的 WinUSB 应用；
- macOS 上的对应 App；
- **没有 Linux 版**。

于是出现一个尴尬局面：

- 硬件在 Linux 下能被识别；
- 但厂商的文件协议没有 Linux 实现；
- 用户看到的不是“网卡”，而是一个“不知道怎么用的设备”。

JD 上有一条很典型的[问答](https://question.jd.com/question/1752311395_4277359_1.html)：

> 问：支持 Linux 吗？Windows 连 Linux，Linux 连 Mac。  
> 答：Windows 和 Ubuntu 之间可以共享鼠标键盘，但不能传数据。

这句话基本概括了成品对拷线的 Linux 体验。

## 不要把它和“普通 USB 数据线”混淆

还有一种更危险的东西：**没有芯片的 USB-A 到 USB-A 双公头线**。

它只是把两端的主机 USB 口硬连在一起，不是对拷线。轻则识别不了，重则损伤 USB 控制器。

真正的对拷线：

- 线中间有桥接芯片（通常有个鼓包）；
- 商品页会写“对拷线/数据传输线”，不是“USB 延长线”；
- 价格通常几十到两百元，不是几块钱。

但即使是真对拷线，也不等于 Linux 可用。

## 一张决策表

| 需求 | 成品对拷线 | Deskflow + 网络 | Samba |
|---|---|---|---|
| Windows↔Windows 键鼠 | 通常可以 | 可以 | 不适用 |
| Windows↔macOS 键鼠 | 通常可以 | 可以 | 不适用 |
| Windows↔Linux 键鼠 | 部分可以 | 可以 | 不适用 |
| Windows↔Linux 文件 | 通常不行 | 不行（设计如此） | 可以 |
| Linux↔Linux 文件 | 部分芯片可以 | 不行 | 可以 |
| 需要额外硬件 | 一根线 | 一根网线 | 一根网线 |
| 需要装软件 | 厂商客户端 | Deskflow | Samba 客户端/系统自带 |
| 成本 | 几十到两百 | 0 元（软件） | 0 元（软件） |

## 什么时候对拷线仍然合理

- 你只有 Windows 和 macOS，且不想组网；
- 你需要“插上就能用”的一次性文件迁移；
- 你不需要 Linux 支持。

如果你有多台机器、有 Linux、还希望长期使用，**网络方案更稳**：

- 键鼠：Deskflow；
- 文件：Samba / SFTP / LocalSend；
- 网络：一根直连网线或同一个局域网。
